# Floating Menus

miniERP currently uses these shared floating surfaces:

- `DropdownMenu` via `src/components/ui/dropdown-menu.tsx`
- `Dialog` via `src/components/ui/dialog.tsx`
- command palette via `src/components/command-palette.tsx` and `src/components/ui/command.tsx`

## Shared Layer Contract

All new floating layers should reuse `src/components/ui/floating-layer.ts`.

- `FLOATING_TOOLTIP_Z`: `z-[60]`
- `FLOATING_MENU_Z`: `z-[70]`
- `FLOATING_DIALOG_OVERLAY_Z`: `z-[80]`
- `FLOATING_DIALOG_CONTENT_Z`: `z-[81]`
- `FLOATING_PANEL_BASE`:
  - `pointer-events-auto`
  - `relative`
  - `isolate`
  - `border border-border`
  - `bg-[hsl(var(--popover))]`
  - `text-[hsl(var(--popover-foreground))]`
  - `shadow-elevated`

## Rules

- Portal floating content to `body` when the Radix primitive supports it.
- Never use `bg-transparent` for menu or dialog panels.
- Floating content must keep `pointer-events-auto`.
- Floating content should use explicit `hsl(var(--popover))` and `hsl(var(--popover-foreground))`
  utilities in this repo. `bg-popover` and `text-popover-foreground` are not generated by the
  current Tailwind token setup.
- Do not downgrade shared layers back to `z-50`.
- Avoid rendering floating content inside non-portaled `overflow-hidden` containers.

## Verification

1. Open `/dev/floating-layers` in development.
2. Open the dropdown and click `Primary menu action`; `Background clicks` should stay at `0`.
3. Open the dialog and confirm the dialog action; it should remain clickable above the overlay.
4. Open the command palette and confirm the panel uses the same opaque floating surface.
5. Repeat in light, dark, and system theme modes.
